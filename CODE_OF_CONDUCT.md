# Contributor Covenant Code of Conduct

## Our pledge

We want a project where people can say "I don't understand this regex" or "I think this
detector is wrong" without paying for it. We therefore commit to a welcoming, professional
environment for everyone, whatever their experience, background, or how they spell
`registrable`.

## Standards

Behaviour that helps this project:

- be specific. "The crawler misses links inside `<picture>`" is a contribution; "this is
  broken" is a puzzle.
- assume the maintainer is busy, not hostile. Silence for a week is usually a week, not
  contempt.
- keep critique about the code. A pull request is not a person.
- accept that some requests are refused for stated reasons (no new dependencies, no headless
  browser in v0.1) and that a refusal is not a verdict on you.
- use content warnings for long rants and paste logs in a fenced block, not the PR
  description body.

Behaviour we will not accept: sexualised language or imagery, personal or political attacks
directed at a person, publishing anyone's private information (including the domains
discovered in someone's private runs), unwelcome solicitation, and gatekeeping ("that's not a
real bug report"). Trolling a bot's maintainer counts too.

## Scope

This code of conduct applies in project spaces (issues, pull requests, discussions, releases,
chat) and in public spaces when someone is representing the project - including at a
conference talk or in a blog post about it. A maintainer's repository permissions are a
trust, not a status; abusing them (merging your own PR to spite someone) is in scope.

## Enforcement

Report unacceptable behaviour to the maintainers at the private-contact address in
[SECURITY.md](SECURITY.md), or through a GitHub private vulnerability report if that reads
better for your situation. Every report gets a response within two weeks; if you think
that is too slow, say so in the report and we will look at it first.

Reports are handled by the maintainers listed in this repository; if a report concerns one
of them, expect it to be escalated to another contributor in good standing, or to
GitHub Support (they can act on repositories and accounts).

Consequences can range from a private note to a temporary or permanent removal from the
project and its spaces, up to a GitHub report. We weigh context, whether the behaviour was
patterned or one-off, and how the person targeted experienced it, and we say what we decided
and why to the people involved - without sharing the report itself.
